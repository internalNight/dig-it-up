# 电脑版进展与非阻塞表面回读（2026-10-07）

## 当前目标和 Git 状态

继续以 Windows 电脑版为优先：保持挖掘操作、地形连续性和寻矿玩法，
逐步提高帧率与沙土表面更新频率。手机移植、实测材料标定和数值收敛
属于后续工作。本轮不改变材料参数或物理时间步。

本轮开始时直接查询 GitHub 全部远端分支，最新提交是电脑性能分支
`codex/desktop-performance-detail` 的 `51c16be`（9 月 28 日）；
月面分支是 `bb557a0`，`master` 仍是最初导入的 `7b5e0a7`。
仓库原先仅配置抓取 master；本轮显式抓取全部分支，避免遗漏进展。

目前已有 100 × 100 m 行驶区域、跟随车辆的 15 × 15 m 局部 MPM 窗口、
访问过的区块在本次会话中的状态保留、月面环境，以及探测并挖出
埋藏金色标本的关卡。它仍是单人原型：车辆外观、玩法深度和完整玩家
验收还有改进空间；当前土体参数也不是实测月壤标定结果。

## 本轮实现

原先 GPU 密度计算后，每次表面重建都调用
`SubmitAndBlockUntilGPUIdle`，在渲染线程等待 GPU 完全空闲。
现在提交持久化 staging-buffer 回读请求，每个游戏帧最多排队一次
GPU fence 查询；仅在 `IsReady()` 后锁定并复制密度，随后继续原来的
工作线程网格提取与游戏线程上传。

保持最多一个表面重建任务在途，避免堆积。退出关卡或销毁 actor 时，
在渲染线程释放待回读资源，并用任务代次阻止旧任务上传到已退出的 actor。
编辑器中的手动预览也允许在回读期间 tick。

这消除了表面密度阶段的强制全 GPU 等待；MPM 求解器自身仍有回读等待，
因此不能称为整个模拟已经完全非阻塞。

## 验证与测量

机器：RTX 4060 Ti 8 GB、i5-13600KF、32 GB RAM、UE 5.8，DX12/SM6，
1920 × 1080 隐藏窗口。每轮截图在表面首次完成后约 25 秒触发，随后
正常退出。下表平均值使用两秒 HUD 窗口，剔除前三个预热窗口及最后
一个截图窗口；每轮保留九个窗口。不同运行模式分别比较。

| 开发编辑器游戏模式 | 游戏 FPS | 物理 Hz | 表面 Hz | 采样表面完成延迟 ms |
| --- | ---: | ---: | ---: | ---: |
| 改动前，主档静止 | 55.30 | 29.98 | 10.18 | 42.88 |
| 非阻塞回读，主档静止 | 58.03 | 29.97 | 9.81 | 63.03 |
| 非阻塞回读，主档脚本挖掘 | 58.64 | 29.99 | 9.93 | 56.84 |
| 非阻塞回读，流畅档静止 | 59.98 | 30.01 | 13.54 | 50.51 |

主档静止帧率在这一对短测中提高约 4.9%，表面更新频率略降，
请求到完成的采样延迟增加约 20 ms，这是逐帧查询 fence 的代价。
表面延迟包含排队、GPU 回读、CPU 提取和上传，不是 GPU 执行耗时。
这些短测没有逐帧 P95/P99 数据，也不证明长时间或所有挖掘场景的性能。

| 独立 Windows 打包版 | 游戏 FPS | 物理 Hz | 表面 Hz | 采样表面完成延迟 ms |
| --- | ---: | ---: | ---: | ---: |
| 9 月 28 日旧包，主档静止（本轮重新测量） | 60.02 | 29.99 | 9.98 | 52.38 |
| 本轮新包，主档静止 | 59.50 | 30.00 | 9.87 | 69.08 |
| 本轮新包，流畅档静止 | 60.02 | 29.98 | 10.01 | 64.47 |

打包版主档没有测出平均 FPS 或表面频率的提升，且表面采样延迟增加。
因此本轮应视为移除一个渲染线程强制等待点与完善测试基础；不能宣称
打包游戏已经获得明显流畅度提升。9 月 28 日文档中的旧测量与本轮
重新测得的旧包数据不同，评估这次改动时应使用同轮同模式的对照。

21 项自动化检查全部通过，零警告、零失败。表面重建测试新增一个
非阻塞异步阶段，逐点比较全部固定点密度值，与同步参考完全一致。
同步参考保留阻塞等待，仅用于自动化测试。

脚本挖掘日志记录了 22 个携带粒子，以及随后 `retention=0`、
`carried=0` 的释放状态。履带支持短暂降至 3/4，之后恢复 4/4，
因此该测试只证明基本挖掘、携带和释放链可运行，不等于完整操作验收。
静止主档与流畅档日志均保持 4/4 支持。截图已检查地面连续性和 HUD。

原日志仅每两秒输出一次，粒子批量回读与该时刻不一定重合，
此时 `carried=-1` 表示没有该次测量，不表示零携带。打包挖掘的初次
验收因这个采样缺口没有取得足够证据。新增测试专用
`-SandInteractionDiagnostics` 后，实际粒子数据到达时输出诊断；
`-Dig` 自动开启它，携带与释放的断言保留。普通游戏不增加日志频率。

补齐诊断后，独立打包版记录最多 25 个携带粒子并随后释放，
日志支持为 4/4；该诊断模式短测平均 58.43 FPS、30.02 Hz 物理、
9.51 Hz 表面更新。诊断会增加 CPU 统计与日志开销，不能与普通静止
模式直接当作同条件性能比较。

打包版跨窗口夹具完成四次移动并返回原点，实际记录四次窗口切换；
局部粒子数从 265,483 变化到 285,241，再恢复为 265,483。
这证明本次局部窗口装载/回返流程运行，不证明所有已挖地形精确保留。
交接时日志出现暂时 0/4 支持，随后恢复；切换的 CPU 工作约 29–35 ms。
这些仍是长距离行驶体验需要进一步优化的部分。

## 重现与启动

运行 `Tools/TestDesktopPerformance.ps1 -Label Main`，或添加 `-Smooth`、
`-Dig`、`-WindowShift`，分别测试对应场景。各场景串行运行，避免 GPU
竞争。结果 JSON、逐窗测量、日志和截图保存在 `Saved/DesktopPerformance/`。
脚本对崩溃、缺失的新日志/截图、测量窗口不足，以及挖掘未记录携带后
释放的情况报错；不以硬编码 FPS 门槛判定不同机器。

`PlayLunarWorld.cmd` 启动主档，`PlayLunarWorldSmooth.cmd` 启动流畅档。
优先使用本轮 `Builds/DesktopAsync_20261007/Windows`，没有本地包时使用
已编译的 UE 编辑器游戏模式。Builds、Saved 和截图继续按仓库规则仅留在本地。

本地压缩包为 `Builds/DesktopAsync_20261007/DigItUpDesktop_20261007.zip`
（354.76 MiB，49 个运行文件条目），不包含测试日志、截图和调试符号。
SHA-256：`45DF4217F1B82AFB83AE4BEEF046BF887370DF22D3E782B04C297ADB8EB91134`。
本轮只在开发电脑运行验证，其他电脑的兼容性仍需实机检查。
各轮测量摘要和预热后的逐窗数值见 `DesktopAsyncReadbackMeasurements.json`。

复现构建使用 ASCII 路径项目目录，在本机对应 junction
`D:\UEProjects\DigItUp`。先用 `Engine/Build/BatchFiles/Build.bat`
构建 `SandExcavatorEditor Win64 Development`；打包使用同目录的
`RunUAT.bat BuildCookRun -project=<项目.uproject> -noP4 -platform=Win64`
`-clientconfig=Development -build -cook -stage -pak -archive`
`-archivedirectory=<输出目录> -unattended -utf8output`。

## 下一阶段验收方向

1. 降低 CPU 网格提取和上传成本，目标是主档表面更新接近 15 Hz，
   同时记录逐帧分位数与操作响应延迟，不能只看平均 FPS。
2. 对重复跨区块行驶、挖坑后离开并返回、履带支持和冻结地形代理做
   长时间回归，检查更新延迟是否影响地形连续性。
3. 完整试玩探测、行驶、挖掘、胜利和继续挖掘流程，记录玩家能否理解
   目标和操作，再决定新增关卡内容。

上述是后续验收方向，本轮只完成非阻塞回读、对应检查与电脑包更新。
